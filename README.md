# 复扫雷 Complexweeper · 单文件网页复刻

**复扫雷**是 青月晓 做的"四种雷"扫雷变体：雷分成 **正实雷 / 负实雷 / 正虚雷 / 负虚雷** 四种；
格子显示的不是"周围有几颗雷"，而是周围所有雷**加和之后的模长**（整数或最简根式）。
四行计雷器分别统计"四种雷各自还没被标记的颗数"，标记（插旗）也要按虚/实、正/负四种类型分别插。

本仓库是它的**网页复刻版**：只有一个 `complexweeper.html`，**零外部依赖**（双击即可打开，
不联网、不引用任何 CDN/字体/图片文件）。玩法、布雷、判据、连锁展开、计时计分与界面版式，
都是**逐函数对照原作者开源源码**重写的等效实现。

- **网页版改版者（HTML 单文件复刻实现）**：DeepSeek V4.1 Flash
- **本网页版版本**：`0.1.1`（版式沿用 `0.1.0`，另加触屏长按插旗／有旗单击换旗，见 §2.1）
- **对齐基准（上游源码）**：<https://github.com/Yueqing-Chen/complexweeper-A-minesweeper-game>
  —— 对齐版本 **1.0.12**（`正式版/src/game.zig`、`main.zig`、`win32.zig`；`assets.zig` 由
  `tools/gen_atlas.js` 从 `素材/图集.png` + `素材/图集.json` 生成）

  > 本仓库是**独立仓库，不是上游的 fork**：上游的 Zig 源码不随本仓库分发，这里只放"源码 → 网页版"
  的等效实现（对照关系见 §1）。上游源码、许可与素材归属请以上游仓库为准。

- **打开方式**：双击 `complexweeper.html`（`file://` 直接可用）。最高分纪录存在浏览器的
  `localStorage` 里，不上传任何数据。
- **玩法速览**：左键翻开 · 右键插旗（正实旗 → 负实旗 → 正虚旗 → 负虚旗 → 无）·
  中键或左右键同时按展开（chord）· `F2` 开局 · 菜单里有初级/中级/高级/自定义/最高分纪录/缩放。

## 1. 原版源码 → 网页版的等效关系

### 1.1 运算与规则层：`game.zig` → `class Board`

| 上游（`正式版/src/game.zig`） | 网页版 | 说明 |
|---|---|---|
| `Rng{a: u32}`、`init`、`next`、`below` | `mulberry32` + `draw(bound)` | 随机数：`a +%= 0x6D2B79F5; t = a; t = (t ^ (t>>15)) *% (t\|1); t ^= t +% ((t ^ (t>>7)) *% (t\|61)); f64(t ^ (t>>14)) / 2^32`，即 mulberry32；`below(n)` = 截断取整，等价于网页版的 `draw(n)`。同种子 ⇒ 同一盘雷 |
| `genBoard(start_cell)` | `deal(firstCell)` | 布雷：首点 + 其 8 邻格**禁雷** → 候选格按格号**升序**入池 → **降序 Fisher–Yates** 洗牌 → 均匀分支 `mine = 1 + below(4)`，或"精确配比"分支（按类型 1→4 铺好后整体降序 FY）。**不动已有的旗**（开局前插的旗要活过第一次左键） |
| `computeClues` | `computeClues()` | `clue[i] = re*re + im*im`（邻域四种雷的实部/虚部分量相加后取模长平方）；统计 `type_total[1..4]` 供计雷器用 |
| `TYPES`、`ACHIEVABLE`、`PRESETS`、`MAX_W/MAX_H/MAX_CELLS/MAX_MINES` | 同名常量 | 四种雷的分量 `(1,0) (-1,0) (0,1) (0,-1)`；可达模长 24 个值 `0,1,2,4,5,8,9,10,13,16,17,18,20,25,26,29,32,34,36,37,40,49,50,64`；三档 `9×9·10 / 16×16·40 / 30×16·99`；上限 宽 40 / 高 30 |
| `cascadeOpen(seeds)` | `floodFill(cells)` | 连锁展开：定长栈 **LIFO**，只对"空白格"（周围无雷）压邻居；压栈时用 `queued[]` 查重（1.0.12 对 1.0.11 漏格的修复，只影响入栈次数，不改结果） |
| `reveal(cell)` | `open(cell)` | 翻开：已翻开/已插旗的格子直接忽略（**旗保护**）；踩到雷 ⇒ 判负；空白格 ⇒ 以**该格的 8 个邻居**为种子 `floodFill` |
| `setFlag`、`cycleFlag` | `setFlagStage`、`cycleFlag` | 旗的循环 `(flag + 1) % 5`，数量不限；`flags_of[1..4]` 同步维护 |
| `unmarked(t)` | `unmarkedOf(t)`、`counterValue(t)` | 计雷器数值 = `type_total[t] − flags_of[t]`，**可以为负**；虚轴两行取负值显示 |
| `matchComboTruth(got, truth)` | `chordCriterion(cell)` | 判据：设 `P = 正实+负实`、`V = 正虚+负虚`，插旗数量 `gP/gV` ⇒ 通过条件 `gP+gV == P+V && ((gP==P && gV==V) || (gP==V && gV==P))`。即"只比实虚比例（或倒数）、不比是哪种雷"，所以判据通过也可能踩雷——这是本作的核心玩法 |
| `tryExpand(cell)` | `chord(cell)` | 展开：仅对"已翻开且非雷"的格子；收集未翻开且未插旗的邻格；判据不过 ⇒ 只提示、**不翻开任何格**；邻格里有雷 ⇒ 翻开第一颗雷判负；否则 `floodFill(targets)` |
| `checkWin` | `checkWin()` | 所有非雷格都翻开才算胜（胜局**不揭示**雷） |
| `splitEvenly(total)` | "按合计均分"按钮 | 自定义雷区按合计均分：`total/4`，余数按类型 1→4 顺序各 +1 |
| 自定义雷区校验 | `validateCustom(h, w, counts)` | 高度 9–30 行、宽度 9–40 列、四种雷合计 ≥ 1 且 ≤ `宽×高 − 9`（首点 + 8 邻居必须留空）；合计 ≤ 0 取 99、≥ 999 取 999；错误文案与原件一致 |

| `FACE_FLASH_MS`、`faceSprite()` | `faceFlashUntil`、人脸状态机 | 人脸贴图优先级：按住人脸 → 胜/负 → 有键按住（"扫"的表情）→ 动作后 200 ms 的"扫" → 常态 |

### 1.3 素材层：`assets.zig` / `素材/图集.*` → 内嵌图集

- 上游把 `素材/图集.png`（256×87 RGBA）+ `素材/图集.json`（61 个槽位，**槽位顺序即贴图 id**）
  在构建时生成成 `assets.zig`。网页版把**同一张图集**以 base64 内嵌（`ATLAS_B64`），并按
  同样的 61 个矩形（`RECT`）与 65 项"模长 → 数字贴图"表（`D_TO_SPRITE`）切图 —— 经逐条比对，
  **矩形 61/61、映射 65 项 0 处不一致**。
- 四种雷/四种旗/数字/爆炸/人脸共用的都是这一张图集，所以网页版不需要任何外部图片文件。

## 2. UI 界面是怎么搭的

网页版把界面拆成两层，正好对应原件的"窗口外壳 + 客户区自绘"：

1. **客户区 = `<canvas>` 整帧绘制**：棋盘、四行计雷器、LED 数码、人脸、计时器、立体边框全部
   按 §1.2 的公式画在同一张画布上；格子边长 16 px，缩放档位 100 / 200 / 300%。
2. **窗口外壳 = DOM/CSS**（对应上游 `win32.zig` 建窗口的部分）：Win95 风格标题栏（程序图标 +
   "复扫雷 Complexweeper" + 最小化/最大化/关闭按钮）、菜单栏、下拉菜单，以及"玩法与操作"、
   "关于复扫雷"、"自定义雷区"、"最高分纪录"四个居中对话框；桌面背景是原件的青色。

一个实现细节（也是踩过的坑）：**窗口宽度必须跟随客户区**（`宽度 = clientW`），标题栏文字过长时要
裁切而不是把窗口撑宽 —— 原件的标题栏会把标题截成"复扫雷 Compl…"，而网页版若让标题栏参与定宽，
窄棋盘（初级 9×9）就会出现"棋盘看起来没居中"的观感问题。

### 2.1 触屏插旗（手机／平板）

**版式不做手机适配**：模拟窗口保持桌面固定像素尺寸，画面比屏幕大时就靠浏览器自己的缩放与滚动
——拖动=平移画面、单击=翻开格子都是浏览器原生行为，网页版没有插手。只在上面补了两个原件没有的
触屏动作（鼠标操作完全不受影响）：

- **长按 420 ms**：未翻开的格子 → 插正实旗（阶段 1）；已有旗的格子 → 取消旗（阶段 0）。
- **有旗的格子单击**：换成下一面旗（正实→负实→正虚→负虚→正实，即 1→2→3→4→1）。
  这里**故意不经过"无旗"**：单击是高频动作，让它走满圈容易把旗误擦掉，取消旗统一交给长按。
- 无旗的格子单击照旧是翻开（走浏览器补发的 click → 鼠标路径）；手指一动（> 10 px）就放弃长按，
  把滚动还给浏览器；人脸、已翻开的格子、界外一律不拦截。

实现要点（`bootTouch()`，只认 `pointerType !== "mouse"`，鼠标路径一字未改）：触屏手势结束后浏览器
还会补发一套 `mousedown/mouseup/click`，若不吞掉，"长按插旗"会顺手把格子翻开；因此用 `armSwallow()`
记一次"待吞"，由 `touchOwned()` 在 canvas 的 `mousedown` 与 window 的 `mouseup` 处消耗掉（700 ms 兜底过期，
免得滞留时吃掉混合设备上的真实鼠标点击）。画布上只加了 `-webkit-touch-callout:none` 之类的
"长按不弹系统菜单／不选中文字"抑制，**故意不设 `touch-action`**（否则原生拖动平移就没了）。
"玩法与操作"里另有一段触屏说明。

触屏没有中键，所以**判据展开（chord）暂时只能在电脑上用中键或左右键同按**——需要的话可以再加"双击"。

> 本节内容自 **`0.1.1`** 起才有；`v0.1.0` 标签是不含触屏动作的纯桌面版本。

### 2.2 调试用的 URL 参数

这些开关是开发与验收时用的，正常游玩直接双击打开即可，完全不需要它们：

| 参数 | 作用 |
|---|---|
| `?preset=beginner\|intermediate\|expert\|custom` | 直接按指定难度开局（`custom` 走 12×12、正实 7 + 负虚 7 的调试盘） |
| `?zoom=1\|2\|3` | 缩放 100% / 200% / 300%（等价于菜单里的缩放项） |
| `?demo=1..4` | 载入固定局面（种子与首点写死，便于复现）：1 = 中级已翻开 103 格 + 6 面旗；2 = 踩雷局面；3 = 胜利局面；4 = 自定义盘 |
| `?bare=1` | 只画画布、不画 Win95 外壳 —— 用于把渲染结果与原件截图做**整帧逐像素**比对 |
| `?show=howto\|about\|custom\|records` | 启动即弹出对应对话框（截图用） |
| `?touchtest=1\|flag` | 用合成的 `PointerEvent` 跑一遍触屏序列，把结果写进 `document.title`：`1` = 长按→单击→单击→长按；`flag` = 只长按一次、把旗留在画面上便于截图核对 |

开发过程中用 `?bare=1` 与固定局面，对 5 种版式做过**整帧逐像素 0 差异**核验（含 100/200/300% 缩放、
胜利/判负/连锁展开等状态）；这几个参数就是那套核验的入口，留着方便任何人重跑。

## 5. 关于"逆向"

在找到原作者的开源仓库之前，这个项目是从 `复扫雷 1.0.11.exe` 二进制起步的：当时判定了它由
**Zig 0.16.0 / ReleaseFast / `x86_64-windows-gnu` / 不链接 libc** 编译，并靠反汇编还原出布雷、
随机数、判据、连锁展开等算法，做到"行为等价重建 + 整帧逐像素一致"。
后来确认原作者源码已开源，于是**对齐基准统一改为上游源码**（§1 的表即对照结果），逆向结论只作
能力留档、不再作为标准。因此本 README 不再展开逆向过程，只讲"源码 → 网页版"的等效关系。

## 6. 版本说明

- 对齐的上游版本：**1.0.12**。

  1.0.12 用 `queued` 查重修掉了；网页版采用**修复后**的行为。
